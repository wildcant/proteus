# Supported Carriers

The Envia Shipping API gives you a **single integration** for dozens of carriers across domestic and international lanes. Use one API to get quotes, create labels, schedule pickups, cancel shipments, and create manifests—without maintaining separate carrier integrations.

This page lists supported carriers and their capabilities. Use it together with the [Quote Shipment](/reference/shipping-rates) and [Create Shipping Label](/reference/create-shipping-label) endpoints to choose the right carrier and service for each shipment.

## Shipment Types

The `shipment.type` field in the rate and generate requests determines the shipment category:

| Type                      | Value | Description                                                                          |
| :------------------------ | :---: | :----------------------------------------------------------------------------------- |
| Parcel                    |  `1`  | Standard package shipments — supported by all carriers                               |
| LTL (Less than Truckload) |  `2`  | Freight shipments that share truck space — see the **LTL** column in the table above |

The **LTL** column in the carrier table above indicates whether a carrier supports LTL shipments (`shipment.type: 2`). Carriers marked **✘** only support Parcel (`shipment.type: 1`). Sending an unsupported type returns an error.

<Callout icon="🚛" theme="default">
  ###

  **FTL (Full Truckload):** FTL shipments are currently managed through the [cargo.envia.com](https://cargo.envia.com) platform and are not yet available via API.
</Callout>

## Label Format

The **Label format** column shows the exact format as in the carrier spec (e.g. `PDF STOCK_4X6`, `TPAPER_7X4.75`, or dimensions like `4X6.5`). Use the format that matches your carrier when creating labels. Check the [Create Shipping Label](/reference/create-shipping-label) reference and the carrier’s service options for the exact formats and paper sizes available per service.

***

## Getting the full list programmatically

The table above is a snapshot of supported carriers and capabilities. For an up-to-date list of carriers available for a given origin (e.g. country or postal code), use the **Queries API**:

* **[Get Available Carriers](/reference/available-couriers)** — returns carriers that can ship from a specified origin. Use this to show users only carriers that apply to their shipment.

Carrier availability can change with new integrations and regional coverage; always prefer the API response for production logic.
