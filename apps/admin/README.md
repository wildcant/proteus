## Styling

This project uses [Tailwind CSS](https://tailwindcss.com/) for styling.

### Removing Tailwind CSS

If you prefer not to use Tailwind CSS:

1. Remove the demo pages in `src/routes/demo/`
2. Replace the Tailwind import in `src/styles.css` with your own styles
3. Remove `tailwindcss()` from the plugins array in `vite.config.ts`
4. Remove `@tailwindcss/vite` and `tailwindcss` from `package.json`

## Routing

This project uses [TanStack Router](https://tanstack.com/router) with file-based routing. Routes are managed as files in `src/routes`.

### Adding A Route

To add a new route to your application just add a new file in the `./src/routes` directory.

TanStack will automatically generate the content of the route file for you.

Now that you have two routes you can use a `Link` component to navigate between them.

### Adding Links

To use SPA (Single Page Application) navigation you will need to import the `Link` component from `@tanstack/react-router`.

```tsx
import { Link } from "@tanstack/react-router";
```

Then anywhere in your JSX you can use it like so:

```tsx
<Link to="/about">About</Link>
```

This will create a link that will navigate to the `/about` route.

More information on the `Link` component can be found in the [Link documentation](https://tanstack.com/router/v1/docs/framework/react/api/router/linkComponent).

### Using A Layout

In the File Based Routing setup the layout is located in `src/routes/__root.tsx`. Anything you add to the root route will appear in all the routes. The route content will appear in the JSX where you render `{children}` in the `shellComponent`.

Here is an example layout that includes a header:

```tsx
import { HeadContent, Scripts, createRootRoute } from '@tanstack/react-router'

export const Route = createRootRoute({
  head: () => ({
    meta: [
      { charSet: 'utf-8' },
      { name: 'viewport', content: 'width=device-width, initial-scale=1' },
      { title: 'My App' },
    ],
  }),
  shellComponent: ({ children }) => (
    <html lang="en">
      <head>
        <HeadContent />
      </head>
      <body>
        <header>
          <nav>
            <Link to="/">Home</Link>
            <Link to="/about">About</Link>
          </nav>
        </header>
        {children}
        <Scripts />
      </body>
    </html>
  ),
})
```

More information on layouts can be found in the [Layouts documentation](https://tanstack.com/router/latest/docs/framework/react/guide/routing-concepts#layouts).

## Data Fetching

Data fetching uses **TanStack Query** with route loaders for prefetching. API clients are generated by [Orval](https://orval.dev/) from OpenAPI specs.

### Query options pattern

Define reusable query options alongside your API hooks. The route loader prefetches via `ensureQueryData`, and the component reads the cached data with `useSuspenseQuery`:

```tsx
// features/products/api/products.ts
import { queryOptions } from '@tanstack/react-query'
import { getProduct } from '#/api/generated/products'

export const productQueryOptions = (id: string) =>
  queryOptions({
    queryKey: ['products', id],
    queryFn: () => getProduct(id),
  })
```

```tsx
// routes/products/$id/route.tsx
export const Route = createFileRoute('/_authed/_shell/products/$id')({
  loader: ({ context, params }) =>
    context.queryClient.ensureQueryData(productQueryOptions(params.id)),
  component: ProductDetail,
})

function ProductDetail() {
  const { id } = Route.useParams()
  const { data } = useSuspenseQuery(productQueryOptions(id))
  // ...
}
```

The loader ensures data is available before the route renders (no loading spinners). `useSuspenseQuery` gives the component a reactive subscription so it updates on cache changes (e.g. after a mutation invalidates the query).

### Generating API clients

API clients and types are generated from the backend's OpenAPI specs:

```bash
pnpm -w run openapi:generate
```

This produces typed hooks and request/response types in `src/api/generated/`.


## CRUD Pages and Route Modals

Admin CRUD pages use **route-driven modals** — modals that live at their own URL and render as overlays on top of the parent page. This gives us deep-linkable modals, browser back/forward support, and animated open/close transitions.

### Route structure

```
products/
  route.tsx              # /products layout (breadcrumb, <Outlet />)
  index.tsx              # Product list page
  create.tsx             # /products/create — RouteFocusModal (full-screen)
  $id/
    route.tsx            # /products/:id — detail page + <Outlet />
    edit.tsx             # /products/:id/edit — RouteDrawer (side panel)
```

### How modals stay on top of parent content

In TanStack Router, sibling routes replace each other in the parent's `<Outlet />`. The approach depends on the modal type:

- **Full-screen modals** (`RouteFocusModal`): Cover the entire viewport with an overlay, so the parent page being unmounted doesn't matter visually. The list re-renders instantly from React Query cache when the modal closes. Used as a simple sibling route (`create.tsx` alongside `index.tsx`).

- **Partial-screen modals** (`RouteDrawer`): Only cover part of the screen, so the parent page must stay visible. The parent content lives in `route.tsx` (the layout) instead of `index.tsx`, and the modal renders via `<Outlet />` as a portal on top. This is why `$id/route.tsx` contains the detail page directly — so it stays mounted when `$id/edit.tsx` renders the drawer.

### Two modal types

- **`RouteFocusModal`** — Full-screen overlay (Medusa's FocusModal style). Used for **create** flows. `inset-2`, `rounded-lg`, close button + `esc` badge on the left.
- **`RouteDrawer`** — Right-side drawer panel. Used for **edit** flows. `560px` wide, `8px` inset, close button + `esc` badge on the right.

Both share the same route-driven pattern: open on mount, navigate to parent on close, portal-rendered overlay.

### Adding a new CRUD page

1. Create the resource directory under `routes/_authed/_shell/` (e.g. `orders/`)
2. Add `route.tsx` with breadcrumb and `<Outlet />`
3. Add `index.tsx` with the list page (table + `PageLayout.SingleColumn`)
4. Add `create.tsx` wrapping your form in `<RouteFocusModal>`
5. Add `$id/route.tsx` with the detail page content + `<Outlet />`
6. Add `$id/edit.tsx` wrapping your form in `<RouteDrawer>`
